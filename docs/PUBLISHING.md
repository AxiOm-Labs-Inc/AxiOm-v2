# Публичный и приватный репозитории: что куда можно

> Приватный документ: в публичный `AxiOm-v2` не переносить.

## Два репозитория

| Репозиторий | Доступ | Что это |
|---|---|---|
| `AxiOm-Labs-Inc/AxiOm-v2-dev` | 🔒 приватный | **здесь идёт вся работа.** Полное дерево, из него собираются все релизы |
| `AxiOm-Labs-Inc/AxiOm-v2` | 🌍 публичный | витрина: GitHub Releases (APK, Setup.exe), `appcast.xml`, README, код без механики Телемоста |

Приложение обновляется **из публичного** репозитория: берёт оттуда Releases и
`appcast.xml`. Поэтому каждый релиз что-то туда публикует (docs/BUILD_AND_RELEASE.md §9).
А вот **код** туда переносить не обязательно: публичное дерево может сильно
отставать от приватного, на работу приложения это не влияет.

## Главное правило

> Публично можно всё, что показывает, **что функция существует и как ей
> пользоваться**. Нельзя ничего, что показывает, **как устроен Телемост** —
> даже если в файле нет ни одного пароля.

Прежде чем что-то публиковать, спросите себя не «есть ли тут секрет», а
«объясняет ли этот файл постороннему, как работает скрытый механизм».

Мотив не безопасность (её держит авторизация на серверах), а то, что схема
обхода живёт, пока о ней не знают площадки, через которые она работает.

## Что где может лежать

### 🔴 Только в приватном

- `lib/features/wbstream_tunnel/**` — вкладка Телемоста целиком
- `android/app/src/main/kotlin/app/axiom/TunnelMethodHandler.kt`, `TunnelRelayController.kt`
- `core_owner.dart`, `connect_lock_shield.dart` — делёж ядра между VPN и Телемостом
- `android/app/src/main/jniLibs/**` (`librelay.so`) и `android/app/relay.version`
- приватные документы: `docs/ONBOARDING.md`, `REBRANDING.md`, `RELEASE_NOTES_FORMAT.md`,
  `COMMIT_FORMAT.md`, `BUILD_AND_RELEASE.md`, этот файл
- сборочные скрипты: `scripts/build_android.sh`, `build_windows.ps1`, `verify_apk.py`,
  `check_public_tree.sh`
- любые упоминания: WB Stream, Яндекс.Диск/слоты, `librelay`, рукопожатие Телемоста,
  WG-адреса туннеля

### ⛔ Нигде, ни в одном git, включая приватный

- ключ подписи (`*.jks`, `*.keystore`), `android/key.properties`
- `.env` и значение `DEVICE_API_KEY`
- любые пароли, токены, ключи — **и пути к файлам, где они лежат** на чьём-то
  компьютере или сервере

### 🟢 Можно в публичный

- оплата и личный кабинет целиком
- вкладка-заглушка `lib/features/telemost/widget/telemost_placeholder_page.dart`
  (в публичном дереве вместо настоящей вкладки) и флаг доступа `features.telemost`
- обычный VPN-функционал, UI, переводы, Windows-часть
- `README.md`, `LICENSE.md`, `appcast.xml`, `.env.example`, `android/key.properties.example`
- `scripts/fetch_core.sh`

## Как переносить код в публичный

**Никогда не `git merge` приватной ветки в публичную.** Merge тянет запретные
файлы целиком. 04.09.2026 именно так в публичный репозиторий на сутки уехала вся
папка `wbstream_tunnel/`; откатывали force-push'ем, а старые коммиты ещё какое-то
время открывались по прямой ссылке на SHA.

Только **выборочный перенос конкретных файлов** в отдельном клоне публичного:

```bash
git clone https://github.com/AxiOm-Labs-Inc/AxiOm-v2.git axiom-public
cd axiom-public
git remote add private https://github.com/AxiOm-Labs-Inc/AxiOm-v2-dev.git
git fetch private

# что отличается (запретное отфильтровать глазами и скриптом ниже)
git diff --stat HEAD private/master

# перенести конкретные файлы
git checkout private/master -- lib/features/account/ assets/translations/

# файлы, где механика перемешана с обычным кодом (например app.dart подписывается
# на провайдер Телемоста), переносить нельзя как есть — править руками публичную версию

scripts/check_public_tree.sh HEAD     # скрипт берите из приватного клона
git diff --cached                     # глазами: нет ли упоминаний механики
git commit -m "Кабинет: …"
git push
```

`scripts/check_public_tree.sh <ref>` падает, если в дереве есть запретный путь или
слово. Он ловит типовые ошибки, но не заменяет просмотр диффа глазами.

## Работа, сделанная в публичном

Если кто-то закоммитил прямо в публичный репозиторий, эти изменения **не попадут
в релиз**, пока их не перенесут в приватный (релиз собирается из приватного).
Перед каждым релизом — проверка из docs/BUILD_AND_RELEASE.md §9.1. Лучше просто
не коммитить в публичный ничего, кроме `appcast.xml`.

## Описание релиза и коммиты

- Описание GitHub Release публично: только то, что видит пользователь, по
  `docs/RELEASE_NOTES_FORMAT.md`. Никаких WBStream, relay, серверов и «вырезанных модулей».
- Коммиты в публичном репозитории публичны так же, как код: заголовок и тело
  подчиняются тем же правилам (`docs/COMMIT_FORMAT.md`).
